# Hibi — Implementation Issues

このフォルダは、デザインシステムを `kazuki-0418/hibi` リポジトリに実装するための **Issue 下書き集** です。各 `.md` は GitHub Issue にそのまま貼れる形式で書かれています。

## 推奨ワークフロー

```
┌─────────────────────────────────────────────────────────────┐
│  1. このデザインシステムをスキルとして配置                       │
│     - Share メニュー → Download (zip)                       │
│     - hibi リポジトリの `.claude/skills/hibi-design/` に展開  │
│     - .gitignore からは外す (チームで共有する場合)             │
├─────────────────────────────────────────────────────────────┤
│  2. GitHub に Issue を作成                                   │
│     - 下記 `01-*.md` ... `06-*.md` をコピペで Issue 化         │
│     - ラベル付け: `design`, `email`, `web` など              │
│     - マイルストーン: v2.0 (Redesign)                        │
├─────────────────────────────────────────────────────────────┤
│  3. Claude Code に着手させる                                  │
│     $ cd hibi/                                              │
│     $ claude                                                │
│     > /skill hibi-design                                    │
│     > Issue #3 をやって。デザインシステムは `.claude/skills/  │
│       hibi-design/` を見て。PR はブランチ `feat/email-       │
│       redesign` に切って。                                   │
└─────────────────────────────────────────────────────────────┘
```

## Issue の粒度

「1 Issue = 1 PR = 半日〜1日で完結」を狙っています。大きい変更を分割すると、Claude Code (人間も同様) がレビューしやすい PR を出してくれます。
